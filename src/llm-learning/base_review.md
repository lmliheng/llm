## 1. 判定

- **五步顺序全对**：前向 → 损失 → 清零 → 反向 → 更新，而且 `zero_grad()` 正确放在 `backward()` **之前**。这是初学者最高频的错点，你一次过。
- **六处要补**，其中四处（种子、`train()`、`no_grad()`、命名）现在看不出任何差别，但它们是"上大模型才会咬人"的习惯。
- **一个必须做的实验**：你现在的 `lr=0.01 + 1000 步`，打印出来像是收敛了，其实**没到位**——第 3 节给了闭式推导，第 4 节给你要做的事。

## 2. 你写对的地方（不是客套，是这次练习的重点）

| 你写的 | 为什么重要 |
| --- | --- |
| `optimizer.zero_grad()` 在 `loss.backward()` 之前 | PyTorch 的 `.grad` 是**累加**语义。放后面（或忘了写）梯度会带着历史，方向被污染 |
| `loss_fn(y, y_true)` 参数顺序 | 顺序是 (预测, 真值)。MSE 对称掩盖了错误，换成交叉熵就会静默训错方向 |
| 留了 `x=4 → 期望 9` 这个训练集外的点 | 有"训练完要拿没见过的输入验收"的意识，这正是验证集的思想雏形 |

---

## 3. 六处改动

| # | 位置 | 你原来 | 改成 | 不改会怎样 |
| --- | --- | --- | --- | --- |
| 1 | 全局 | 无随机种子 | `torch.manual_seed(0)` | `nn.Linear` 的 w/b 随机初始化，每次跑的轨迹都不同，**任何超参对比都失去意义** |
| 2 | 循环内 | `torch.nn.MSELoss()(y, y_true)` | `loss_fn = nn.MSELoss()` 提到循环外 | 每轮新建一个对象；更糟的是把"配置"当"计算"，这个坏习惯在大模型循环里是实打实的开销。（注：你 example2/3 里本来在循环外，这次凭记忆重写丢了） |
| 3 | 循环变量 | `for epoch in range(1000)` | `for step in ...` | 现在 1 epoch = 1 次更新（full-batch），两者恰好相等；引入 DataLoader 后不再相等，**名字会开始骗人** |
| 4 | 循环开头 | 无 | `model.train()` | Linear 上无差别；一旦有 Dropout / BatchNorm，漏了它训练与验证行为不一致 |
| 5 | 评估段 | `model(torch.tensor([[4.0]]))` | `model.eval()` + `with torch.no_grad():` | 白白建一张计算图再扔掉；大模型上这部分直接吃显存 |
| 6 | 结构 | 平铺的脚本 | `main()` + `if __name__ == "__main__":` | 不利于后面把超参抽出来做扫描；被 import 时会顺手训练一遍 |

**一个真正值得记住的"不这样会怎样"清单：**

- 如果删掉 `zero_grad()` → 梯度累加，每步用的是"历史梯度之和"，等效学习率被放大，loss 会震荡甚至发散。
- 如果 `zero_grad()` 放在 `step()` 之后（循环末尾）→ 其实**仍然能收敛**（只要每次 `backward()` 前已经清零），但一旦循环里出现提前 `continue` 或异常，就会在下一次更新里带上脏梯度。规范位置是 ③。
- 如果 `loss.backward()` 写两次而不 `retain_graph=True` → 报 `Trying to backward through the graph a second time`：计算图在第一次反向时就被释放了。
- 如果 lr 取到稳定上限之上 → 见下一节，loss 直接爆炸成 `nan`。

## 4. 必做实验：1000 步为什么"看起来"收敛了

### 先推公式（这题有闭式解，是最好的显微镜）

数据 `x=[1,2,3]`，`y=[3,5,7]`，模型 `ŷ = wx + b`，`L = (1/3)Σ(wxᵢ + b − yᵢ)²`。记 Σx²=14、Σx=6、Σxy=34、Σy=15：

```
∂L/∂w = (2/3)·(14w + 6b − 34)
∂L/∂b = (2/3)·(6w + 3b − 15)

Hessian H = (2/3)·[[14, 6],
                   [ 6, 3]]  →  λmax = 11.09,  λmin = 0.24   条件数 κ ≈ 46
```

两个数决定了这次训练的一切：

- **学习率上限**：梯度下降在二次函数上的稳定条件是 `lr < 2/λmax = 0.180`。
- **收敛速度由最慢的方向决定**：θ 的误差每步按 `|1 − lr·λ|` 衰减，两个方向各衰减各的，**慢的那个才是瓶颈**。

代入你的 `lr=0.01`：

| lr | 快方向 \|1−lr·11.09\| | 慢方向 \|1−lr·0.24\| | 1000 步后慢方向残留 |
| ---: | ---: | ---: | ---: |
| 0.01（你现在） | 0.889 | 0.9976 | **9.0%** |
| 0.10 | 0.109 | 0.976 | 2.8e-11（到位） |
| 0.20 | 1.22 ❌ | 0.952 | **|因子|>1 → 发散** |

也就是说：`lr=0.01` 时**快方向上千步前就到位了，慢方向 1000 步只走到 9%**。而你 `.4f` 的打印精度会把 `w=1.9xx` 显示得像"已经等于 2"。

### 你要做的三件事（本地跑，把输出贴回来）

1. 原封不动跑一次 base.py，**记下最后一行 loss 和 w、b 的小数点后 6 位**（把打印精度改成 `.6f`/`.8f` 更明显）。
2. 只改 `lr`，分别跑 `0.1` 和 `0.2`，各跑 200 步就够。
3. 对照我的预测（我按上面的推导算的，**没有跑你的代码**）：

   - `lr=0.01`：loss 停在 **1e-5 ~ 1e-3 量级**（取决于随机初始化的误差有多少落在慢方向上），w ≈ 2 但不精确等于 2。
   - `lr=0.1`：loss 掉到 **1e-10 量级以下**，w/b 精确到 2 / 1。
   - `lr=0.2`：几步之内 loss 暴涨，最终 `nan`。

   如果实测和预测不符，那**比符合更有价值**——说明我对初始点或 batch 处理的理解有偏差，我们就对着数字查。
